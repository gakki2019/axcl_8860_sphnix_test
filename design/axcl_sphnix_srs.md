# AXCL Sphinx 文档站需求规格说明

## 1. 文档目标

本项目目标是将 AXCL SDK 文档建设为基于 Sphinx 的双语 HTML 站点，并通过公开 GitHub 仓库接入 Read the Docs 进行版本化发布。

## 2. 范围定义

### 2.1 范围内

- 建立 `docs/` 下的 Sphinx 构建链路。
- 支持 `rst` 与 `md` 混合渲染。
- 建立中英文平行目录和对应导航入口。
- 使用 Read the Docs 原生版本管理能力。
- 在 `design/` 下按需求、设计、验证、TODO 四类独立维护中文文档。

### 2.2 范围外

- `scripts/api` 相关生成脚本改造。
- 现有 C 文档的翻译任务。
- 自定义版本选择器实现。

## 3. 功能性需求

### 3.1 构建与发布

1. 文档站必须可在本地生成 HTML 输出。
2. 文档站必须可通过 Read the Docs 配置接入版本化构建。
3. 默认分支对应 `latest` 版本。
4. 语义化标签 `vX.Y.Z` 对应同名文档版本。

### 3.2 内容组织

1. 中英文目录必须保持平行结构。
2. 空白页必须补齐与所在分类一致的占位内容，不能输出空白页。
3. C/C++ 现有文档必须接入导航树并可访问。

### 3.3 导航与交互

1. 中文为默认入口语言。
2. 任意页面只允许渲染当前语言的侧边栏导航树。
3. 侧边栏默认展开到第二级目录。
4. 页面内需要提供对等语言跳转入口。
5. 目录展开与折叠不得互相干扰同级节点。
6. 父目录折叠后再次展开，子目录状态必须保持。

### 3.4 主题与样式

1. 主题基底固定为 `sphinx_rtd_theme`。
2. 侧边栏视觉和交互行为参考 esp-idf。
3. 渲染过程需要避免首屏闪烁。

## 4. 非功能性需求

1. 构建产物不得提交到 Git。
2. Python 虚拟环境、缓存目录和其他临时文件不得提交到 Git。
3. 需求、设计、验证文档之间必须逻辑一致，不能互相冲突。
4. 任务状态只能维护在 TODO 文档中。

## 5. 验收口径

1. 本地执行 HTML 构建成功并生成 `docs/build/html`。
2. 中英文首页、基础文档、开发文档、FAQ 页面均可访问。
3. Markdown 页面可以正确渲染。
4. C/C++ 文档可从导航树进入。
5. 验证文档中定义的 smoke 与全量测试用例具备明确步骤和预期结果。
6. HTML 测试报告可在 `docs/build/html` 中阅读。
