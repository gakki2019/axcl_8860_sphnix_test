
## 总体说明
1. 构建为基于 Sphinx 的 HTML 站点，并通过名为 `axcl_8860_sphnix_test` 的公开 GitHub 仓库托管到 Read the Docs。
2. 使用 Read the Docs 进行版本管理，而不是维护自定义版本选择器。
3. 中英文内容目录保持平行。
4. 生成产物不提交到 Git。
5. 支持md渲染,如果不支持md渲染, 则需要将md的内容转成可渲染的格式，但尽量保持md的格式不变。
6. 支持中英文双语，任意英文或中文页面都应只渲染当前语言的 sidebar 导航树。不能把两棵语言树同时挂在根 sidebar 下。
7. 默认使用sphinx_rtd_theme
8. 渲染要防闪烁

## 导航栏
1. 布局
```text
基础文档
    - 概览
    - 安装指南
    - 快速开始
开发文档
    - 架构
    - C/C++
    - Python
FAQ
语言切换
```
2. 默认显示中文
3. 默认展开到第二级目录
4. 导航栏的背景色，选中高亮等风格参考 https://docs.espressif.com/projects/esp-idf/zh_CN/latest/esp32/index.html
   源码：https://github.com/espressif/esp-idf/tree/master/docs
   你要抓取esp-idf的展开，折叠状态，复刻hover，高亮，背景色的变化
5. 目录展开和折叠不能影响其他所有同级目录，比如展开`基础文档` 不能影响`开发文档`和`FAQ`同级目录的展开和折叠
6. 父目录展开和折叠不能影响其子目录，比如C/C++是展开的，当开发文档折叠后再展开，C/C++依然是展开的
7. hover高亮文本颜色只对当前focus的栏目生效，其父目录不需要高亮
8. 复刻esp-idf的折叠和展开图标，图标的大小风格要一致
9. 目录和叶节点要按照层级严格对齐，绝对不能因为折叠和展开状态变化影响对齐
10. 折叠展开图标和目录文本效果要一致，绝对不能点击折叠展开图标和点击目录文本表现形式不一致，且图标折叠和展开变化和目录的展开和折叠状态是一致的

## 版本管理
1. Read the Docs 的版本对应 Git 分支和 tag。
2. 默认分支构建 `latest`。
3. 发布 tag `vX.Y.Z` 构建 `vX.Y.Z` 文档版本。
4. Read the Docs `axcl_8860_sphnix_test` 文档 tag 应与 AXCL SDK 发布 tag 保持一致。
5. 版本管理选择样式复刻 https://docs.readthedocs.com/platform/stable/

## 构建产物

构建生成到build/html目录、
以下生成产物不应提交：

1. Sphinx HTML output.
2. Python 虚拟环境。
3. Python 缓存目录。
4. 其他缓存目录

## 文档
1. design目录为文档目录
2. memory必须按照软件设计工程的需求，设计，验证，TODO 分开存储到本目录，分别为:
   - axcl_sphnix_srs.md
   - axcl_sphnix_design.md
   - axcl_sphnix_testcase.md
   - axcl_sphnix_todo.md
3. 必须按照分类来存储文档，比如待开发任务和已完成任务只能在todo.md中更新。
4. 需求，设计，验证必须要保存逻辑一致，不能有冲突和违背。
5. 文档都统一为中文
6. 验证要详细写明用例步骤和预期结果，用例等级(smoke冒烟和全量)，测试报告输出到docs/build/html，输出格式要可阅读
