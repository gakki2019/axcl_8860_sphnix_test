# 日志收集

`axcl-collect-logs` 用于在使用 AXCL 遇到问题时一键收集日志。它把主控和所有 AXCL 设备的日志打包成一个文件，你只需把这个文件发给技术支持。

即使设备已经无响应，也可以运行该工具：主控上的日志照常收集，无响应的设备在等待超时后跳过。

## 1. 快速使用

在主控上执行：

```bash
sudo /usr/local/axhelix/bin/axcl-collect-logs -o /tmp
```

运行结束时，最后一行显示生成的日志包，例如：

```text
archive: /tmp/axhelix_logs_20261031_105529_816.tar.gz
```

把这个文件发给技术支持即可，文件名包含生成时间。`-o` 指定日志包的保存目录，不指定时保存在当前目录。很多系统重启后会清空 `/tmp`，请在重启前把日志包发出或复制到其他目录。

```{note}
建议使用 `sudo` 运行，并写完整路径（使用 `sudo` 时只写命令名会提示找不到命令）。不使用 `sudo` 也可以运行，但部分内核日志和驱动状态需要管理员权限才能读取，这些内容会缺失；工具结束时会给出用 `sudo` 重新运行的完整命令。
```

````{note}
如果应用通过环境变量 `AXCL_HOST_LOG_DIR` 或 `AXCL_DUMP_DIR` 把日志或崩溃文件放到了其他目录，请在设置了这些变量的终端中改用 `sudo -E` 运行，否则工具找不到这些目录：

```bash
sudo -E /usr/local/axhelix/bin/axcl-collect-logs -o /tmp
```
````

## 2. 命令行参数

```text
axcl-collect-logs [options]
```

| 参数 | 说明 |
| --- | --- |
| `-o, --output <dir>` | 日志包的保存目录，目录不存在时自动创建。默认为当前目录。 |
| `-d, --device <list>` | 收集哪些卡的日志：`all` 为全部卡（默认），`none` 为不访问设备、只收集主控日志，也可以指定卡号，如 `0` 或 `0,2`。卡号从 `0` 开始，超出实际卡数时直接报错退出。只有某张卡有问题时，只收集这张卡会更快。 |
| `-t, --timeout <sec>` | 收集每张卡日志包的最长等待时间，单位为秒，取值范围 `40`～`300`，默认 `120`。设备日志很多时可适当加大。收集日志包之前读取设备状态的时间不计入 `-t`，每项最多约 30 秒；所有卡合计（含读取设备状态）最多约 5 分钟。 |
| `-v, --version` | 显示版本并退出。 |
| `-h, --help` | 显示帮助并退出。 |

在脚本中调用时，可根据返回值判断结果：`0` 表示已生成日志包（个别内容收集失败也返回 `0`），`1` 表示参数错误（包括卡号超出实际卡数），`2` 表示无法生成日志包。

## 3. 收集的内容

| 类别 | 内容 |
| --- | --- |
| 主控系统 | 操作系统版本、CPU、内存、磁盘空间、PCIe 设备列表与拓扑，以及从根端口到每张卡整条 PCIe 链路（含中间的 PCIe Switch）的详细信息 |
| AXCL 安装 | 安装包版本与完整性校验、安装和卸载日志、驱动编译状态 |
| 内核与驱动 | 内核日志（含上一次启动）、硬件中断统计、AXCL 驱动模块的版本、参数和运行状态 |
| AXCL 运行 | 主控上的 AXCL 运行日志、应用崩溃时生成的崩溃文件（minidump）、AXCL 相关环境变量 |
| 设备 | 每张卡的系统日志、AXCL 日志、崩溃文件、内核日志、硬件中断统计、内存信息和驱动运行状态 |

- 日志包中的 `summary.txt` 列出了每一项是否收集成功。
- 工具不收集个人文件、家目录、完整的环境变量和进程列表。
- 日志包对所有用户可读（保存在网络存储上时，也包括其他主机的用户），便于在共享目录中直接取用。日志包中包含内核日志、驱动状态和程序崩溃转储等内容，在多人共用的主机上请输出到只有自己能访问的目录，或收集后及时转移。

## 4. 运行时间与中断

- 通常几十秒内完成。设备无响应或日志很多时会慢一些，但工具最长约 7 分钟内一定结束。
- 运行中按 `Ctrl+C` 会停止收集，已收集到的内容仍会打包成日志包。进入打包阶段（屏幕显示 `packing archive`）后 `Ctrl+C` 不再生效，等待打包完成即可，通常只需几秒。

## 5. 常见提示

| 提示 | 说明与处理 |
| --- | --- |
| `not run as root, some items were skipped` | 没有使用 `sudo`，部分内容缺失。请按提示的命令用 `sudo` 重新运行。 |
| `output directory ... is inside ..., which is collected` | 日志包不能保存到会被收集的日志目录（`/tmp/axcl`、`/var/log/axhelix`）里。用 `-o` 换一个目录，例如 `-o /tmp`。 |
| `bash 5.0 or later is required` | 系统的 bash 版本过低，工具无法运行。AXCL 支持的系统都自带 bash 5.0 及以上版本，请确认系统符合 AXCL 的安装要求。 |
| `cannot write to output directory` | 输出目录（未指定 `-o` 时为当前目录）不可写。用 `-o` 指定一个可写的目录，例如 `-o /tmp`。 |
| `WARN: device/<N>/device<N>_collect-log.txt: failed` 或 `timeout` | 第 `N` 张卡的日志没有收集到，其他内容不受影响；设备无响应或日志过多时显示 `timeout`。原因记录在日志包中，直接把日志包发给技术支持即可。 |
| 其他 `WARN: <项目>: failed`、`timeout` 或 `partial` | 该项没有收集到或不完整（例如不使用 `sudo` 时部分驱动状态读不到），其他内容不受影响，日志包照常生成。直接把日志包发给技术支持即可。 |
| `WARN: cannot set the archive permissions` | 输出目录不支持修改文件权限（例如部分网络存储），日志包已生成，但其他用户可能无法读取。需要共享时可用 `-o` 换一个目录重新运行。 |
| `summary.txt` 中提示设备上可能残留临时文件 | 设备日志过多或收集被中断。确认没有其他收集任务在运行后，可用 `axcl-smi sh -d <N> "rm -rf /opt/data/.collect_* /opt/data/device<N>_log_*.tar.gz"` 删除，两处 `<N>` 都换成卡号，例如第 0 张卡为 `axcl-smi sh -d 0 "rm -rf /opt/data/.collect_* /opt/data/device0_log_*.tar.gz"`。 |
